# Pre-reboot rules — applies to every distro

These are the things QuickHatch's pre-reboot guard checks BEFORE
letting the agent issue `reboot`. Every check is distro-aware; the
underlying invariants are the same. If any FAIL, the reboot is
blocked and the failure list is fed back to the agent.

Memorize the invariants — fix them BEFORE issuing reboot, not after.
A broken first boot drops to emergency mode and is only recoverable
by re-mounting from the live USB.

## The seven invariants

### 1. `/etc/fstab` exists and is non-empty
Without it, systemd's fstab generator can't mount the root, swap, or
EFI partitions. Generated by `genfstab -U /mnt >> /mnt/etc/fstab` on
Arch/Alpine, by debootstrap automatically on Debian/Ubuntu, by
Anaconda/dnf on Fedora.

### 2. Kernel + initramfs both present in `/boot`
- Arch / Fedora / SUSE / Void / Alpine: `vmlinuz-*` + `initramfs-*.img`
- Debian / Ubuntu / Mint / Pop / Kali: `vmlinuz-*` + `initrd.img-*`

If missing, the bootloader has nothing to load. Generators per family:
- **mkinitcpio** (Arch, Alpine, Artix): `mkinitcpio -P`
- **initramfs-tools** (Debian, Ubuntu, Pop, Mint, Kali, Parrot, Zorin):
  `update-initramfs -u -k all`
- **dracut** (Fedora, RHEL clones, openSUSE, Void, Nobara, Bazzite):
  `dracut --regenerate-all -f`

### 3. Initramfs newer than its config
Edit `/etc/mkinitcpio.conf` / `/etc/initramfs-tools/conf.d/*` /
`/etc/dracut.conf.d/*` then forget to regenerate, and the running
initramfs is stale. The guard mtime-checks the latest config file
against the latest matching image.

### 4. LUKS plumbing — the silent killer

If ANY block device is `crypto_LUKS`:

a) **Initramfs must include the unlock module:**
   - **Arch family** (mkinitcpio): `HOOKS=` line must contain
     `encrypt` (between `block` and `filesystems`) or `sd-encrypt`
   - **Debian family** (initramfs-tools): `cryptsetup-initramfs`
     package installed AND `/etc/crypttab` populated with at least
     `cryptroot UUID=<luks-uuid> none luks`
   - **Fedora/SUSE/Void family** (dracut): the crypt module must be
     in the built initramfs (verify with `lsinitrd <initramfs.img>
     | grep crypt`) AND `/etc/crypttab` populated

   ⚠️ **Most common failure**: HOOKS edited but `mkinitcpio -P` not
   re-run, OR `cryptsetup-initramfs` not installed before
   `update-initramfs`. Result: kernel boots, initramfs stalls
   waiting for `/dev/mapper/cryptroot` that no module knows how to
   create, then drops to emergency mode after 90s.

b) **Kernel cmdline must reference the LUKS container:**
   The `cryptdevice=UUID=<luks-uuid>:<name>` (Arch/SUSE) or
   `rd.luks.uuid=<luks-uuid>` / `rd.luks.name=<luks-uuid>=<name>`
   (Fedora/dracut) parameter is what tells the initramfs what to
   unlock. Lives in:
   - `/etc/default/grub` → `GRUB_CMDLINE_LINUX_DEFAULT="…"`
     (then run `grub-mkconfig` / `grub2-mkconfig`)
   - `/boot/loader/entries/*.conf` → `options …` (systemd-boot)
   - `/etc/kernel/cmdline` (UKI / mkinitcpio's --cmdline)

   Without it, the initramfs prompts for nothing — just times out.

### 5. Bootloader files exist on disk
Check `/boot/grub/`, `/boot/grub2/`, or `/boot/EFI/systemd/` +
`/boot/loader/`. If empty, the firmware will skip the disk and the
machine boots straight back to BIOS / "no boot device" screen.

Install commands per setup:
- **GRUB-BIOS:** `grub-install --target=i386-pc /dev/sdX`
- **GRUB-EFI:** `grub-install --target=x86_64-efi --efi-directory=/boot --bootloader-id=GRUB`
  (Fedora/SUSE: `grub2-install` + `grub2-mkconfig`)
- **systemd-boot:** `bootctl install`

### 6. `grub.cfg` newer than `/etc/default/grub`
Editing `GRUB_CMDLINE_LINUX_DEFAULT` doesn't take effect until
`grub-mkconfig` / `grub2-mkconfig` regenerates `grub.cfg`. The
guard mtime-checks them.

### 7. Root recovery path exists
At least ONE of:
- Root has a real password (not `*`, `!`, `!!`, `x`)
- A user belongs to `wheel` (Arch/Fedora/SUSE) or `sudo`
  (Debian/Ubuntu) AND `/etc/sudoers` (or a file in `/etc/sudoers.d/`)
  grants that group via `%wheel ALL=(ALL:ALL) ALL` or
  `%sudo ALL=(ALL:ALL) ALL`

Without this, ANY first-boot failure becomes unrecoverable —
sulogin refuses to drop into a shell on a locked root account, and
without a sudoer there's no way back in over SSH either. Set a root
password with `passwd` inside chroot if nothing else.

## What the guard does on failure

Every failed check is fed back to the LLM verbatim with the fix
direction. The agent should address the listed failures with concrete
commands BEFORE attempting reboot again — not just probe more.

If the agent can't reason about a specific failure, it should ask
the user via `/api/ask` rather than reboot anyway.

## What the guard CAN'T catch

- Wrong UUID in cmdline that happens to be syntactically valid
  (the partition exists but isn't actually the LUKS root)
- BIOS settings the agent has no visibility into (Secure Boot
  enabled, CSM disabled mid-install, fast-boot skipping the USB)
- Hardware-specific quirks (NVMe namespace numbering, USB
  enumeration order changing between live env and installed boot)

These remain failure modes the user must diagnose on the target
console. The post-reboot reconnect-timeout message lists them as
likely causes when SSH doesn't come back.
